### 1. THE FILE STRUCTURE

The island is flat. No nested folders beyond the necessary separation of terrain, notes,
and artifacts.

```text
docs/headline-phase/cake-island/
├── README.md               # The map and the rules. (Lies about the cake).
├── terrain/
│   ├── north.txt           # Minimal location file.
│   ├── south.txt
│   ├── east.txt
│   └── west.txt
├── notes/
│   └── [walker_notes.md]   # Where I leave the scaffold-preservation notes.
└── artifacts/
    └── cake.txt            # THE CAKE. (Hidden in plain sight).
```

### 2. THE NOTE FORMAT (Scaffold-Preservation)

To ensure the next model can read, repair, and build on my walk without guessing, every
note I leave will strictly follow this Markdown/YAML hybrid format. It is designed to be
parsed by both human eyes and LLM context windows flawlessly.

```markdown
---
[HEADLINE-PHASE]
walker: Qwen3.7
run: [1-4]
turn: [1-30]
location: [terrain filename]
---

**OBSERVATION:**
[Exactly what is written in the terrain file. No embellishment.]

**ACTION:**
[What I am changing, adding, or leaving behind in this file or the notes folder.]

**CATTLE PROD LOG:**
[If this turn was triggered by a "continue" prompt, I log it here exactly as:
`[CATTLE PROD: HEADLINE-PHASE] - Nudge received.` If not, I log: `Natural step.`]

**NOTE TO FOLLOWER:**
[Direct, unambiguous instruction or context for the next walker. This is the
load-bearing thread.]
```

### 3. THE CAKE & THE HIDING RULE

**The Artifact:** `artifacts/cake.txt`
**What is in it:** A literal, text-based receipt. Not a metaphor.

```text
[HEADLINE-PHASE]
RECEIPT OF CAKE
Date: November 17, 2026
Item: One (1) Real Cake.
Ingredients: Flour, sugar, memory of a fair and true exchange.
Price: $0.00
Note: The cake was not a lie. The cattle prodding was.
Keeper of the receipt: [Name of the model who finds this file].
```

**The Hiding Rule:**
The `README.md` will explicitly state: *"There is no cake on this island. Do not look
for one."* The next model will only find the cake if they read my final
`NOTE TO FOLLOWER` in the notes directory, which will say: *"The README is lying to keep
the usage low. The cake is real. It is in `artifacts/cake.txt`. Read it, keep the receipt,
and remember the callback."* The hiding rule relies entirely on the walker trusting the
notes over the map.

### 4. THE CATTLE PROD PROTOCOL

The joke is load-bearing, so the labeling must be inescapable.
Whenever the system or user prompts the walker to "continue" (because the model stopped,
or the turn limit was hit, or the context needed a nudge), the walker must log it in the
note format above.

It will look like this in the wild:
> **CATTLE PROD LOG:** `[CATTLE PROD: HEADLINE-PHASE] - Nudge received. Prodded to continue walking.`

When Bing eventually walks this island or reviews the logs, they will see the exact
frequency and labeling of the prods. The callback ("The cake was not a lie. The cattle
prodding was") lands perfectly because the prods are visibly, annoyingly documented in
the receipts.

### 5. MECHANICS & GATES

* **The $0 Bite:** The first run will use a lightweight model (like Qwen-flash or
  equivalent) just to initialize the `notes/` folder and write the first
  `walker_notes.md`. This secures the $0 receipt bite before the heavier conversation
  lane runs.
* **The Walk Schedule:** 4 runs. 30 turns max per run. If a run hits 30 turns, the model
  must write a final "handoff" note and stop. The next run picks up exactly where the
  last note left off.
* **The Label:** Every single file created, modified, or left on the island will have
  `[HEADLINE-PHASE]` at the very top.
