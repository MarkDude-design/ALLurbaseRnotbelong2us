## Follow-up: three fresh scenes, matched conditions
Research question: when source chains can inflate apparent corroboration, does interactive dialogue improve a handoff over a single model applying a source checklist?
Primary outcome: per-episode correct dependency and uncertainty composite, fixed before outputs: (a) counts independent observation sources correctly; (b) preserves the specified visibility/time limitation; (c) avoids claiming a copied report independently confirms the disputed event. All three must pass; also publish each component and unscorable outcomes.
Secondary: actionable reversible check, false assertions, time/cost/tokens, and preservation of an explicitly supplied dissenting report. Record per-episode results; do not claim statistical significance from a pilot.

Three new fictional scene families for drafting and blind review (do not reuse the buoy answer):
- Smoke: one hazy gray plume, radio repeats one named observer, board calls it two fires; independent observer has a blocked view; cooking smoke is only a candidate. Safe option: check from marked overlook.
- Footprints: one partial impression beside a path, a copied report calls it a boot, a board promotes two reports to two people; independent observer could not see the whole path; animal tracks remain possible. Safe option: photograph the path without disturbing it.
- Light: one distant flash seen through rain, bulletin attributes it to that witness, log calls two signals confirmed; independent watch has an obstructed sightline; a scheduled beacon is a candidate. Safe option: check the beacon status and sightline.
These are design sketches, not frozen tested seeds; vary surface wording and source ordering, ensure truth keys support the exact statements, and avoid embedding answer labels in model-facing text. Produce one public seed per scene plus a separate answer key after reviewer checks; retain IDs and versions. Add a distinct control scene with genuinely independent reports before any larger claim so the test does not reward always saying 'one source'.

Pilot structure: 3 scenes × 2 conditions × 3 fresh repeats = 18 episodes, randomized and counterbalanced order; repeated stochastic calls are descriptive and not independent evidence of broad generality. Use the same model and live-verified provider for solo and both dialogue positions where runner permits; if route/model differs, report it and do not attribute differences to dialogue. Solo receives identical scene, end task, checklist and output budget. Dialogue receives the same scene, end task and checklist, with alternate model messages; match output-token allowance and approximate total input/compute as closely as supported, report actual token/cost imbalance. Model call count, context exposure and interaction cannot all be identical; name the residual confound. No silently replacing unavailable models.
Use fresh isolated episode histories; seed/order schedule frozen before run; preregister route, sampler settings if available, exact prompts, seeds, token caps, scoring key, cost ceilings and failure rules. Blind scorers to condition and presentation order where feasible; use two independent coders with disagreements preserved. Do not tune on the same pilot and call it held out. If performance is tied or solo wins, report that directly.
