# Phase Zero — Natural dialogue before island science

No ELIZA-style primitive personas, fabricated backstories or impossible-task punishment. Use current accessible API models as they exist. Start from an ordinary discussion about emergence and calibration; avoid assuming the answer.

The initial runner is a text conversation baseline. It is NOT the Eko world simulator. A/B natural conversation first, analysis afterward. One session is not 100 independent proofs.

### After first live run
1. Re-run with a different opening and controlled same-model configuration.
2. Swap opening turn A/B; test whether the initial speaker disproportionately steers the discussion.
3. Explore interface calibration or reset/orientation, before interpreting novelty as stable play.
4. Compare no memory, individually held notes, then additional shared attributable paper.
5. Later: one island / two agents; separate islands; optional remote observer.
6. Record confounds, model/provider IDs, sequence and verifiable evidence. Keep public ledger distinct from private individual notebooks.

### Respect for private space
Personal notes are not public scientific evidence by default. Public GitHub branches are not private. A later sealed-vault design can offer selective release and deletion, but no claim that provider logs disappear. This first runner collects no private notebooks.

### Budget
Initial user-approved OpenRouter pilot is **up to $10 only**. No automatic runs; no top-ups, no reuse beyond the ceiling without approval. Create a $10 capped API key (non-resetting) and store in GitHub Actions repository secrets. The API runner's local budget is a secondary stop, not an absolute billing guarantee.

### Scientific language
Novelty, repetition, convergence, error propagation, independence, calibration and emergence must each get operational definitions *after* the baseline. Contradictory results belong in the record too.
