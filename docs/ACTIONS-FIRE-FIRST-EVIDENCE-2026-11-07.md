## Execution order, with clear stopping points

1. **Already triggered today:** one demo command per Circle prefix. Review current claimed, completed, and still unverified comments. Four near-contemporaneous comments exist; the GitHub shared login alone cannot identify which seat initiated the other two. Don't double-fire paid calls by assuming separate comments are separate authenticated seats.
2. **Queue custody smoke:** one zero-spend pending Z Desk fixture created on `bus`. Verify which consumer (cron/manual) takes it, and preserve claim/done/status artifacts. The queue previously was empty; the new fixture makes exactly one due demo entry.
3. **Owner manual Z Desk demo**, followed by **Circle frozen audit solo/trio**, provided the current provider key/STOP are verified. Three independent soft-$1 audit shots is reasonable; no target to burn dollars.
4. **Island 4-turn proxy** and **Council Matrix** only after verified model IDs, hard key cap, cost receipts and specific experiment value. This is a one-week data plan, not a simultaneous mass dispatch.
5. **No need to fire a PR-only test** without a real code change. Don't delete or disable prior to comparing unique receipts; in particular, disabling an entire GitHub workflow removes *manual dispatch too*. To stop cron but keep the manual button, a code change must remove the schedule trigger.

## What to bank before evaluating deletion

For every execution: workflow name, URL/run ID, trigger and branch/source SHA, owner click versus schedule/comment, exact inputs (no secrets), UTC start/end, attempted HTTP count and retries (or UNKNOWN), accepted outputs, error/STOP status, provider/model claimed vs returned, cost actual/zero/UNKNOWN, artifact ID and expiry, bus path and independent verification result.

Preserve non-replay uncertainty: a successful GitHub job is not proof every external request succeeded, and a completed desk consult is not automatically a correct experiment. A failed run with evidence may be more informative than another easy PASS. Keep old runs containing unique failure logs even if summary files are banked.
