# Circle consult — kulay.love: website build path + picture-posting (public-safe)

Object: a small family crochet website (domain registered). This is an independent outside read, not a seat, not an audit. Public-safe only: no personal details, no people, no private material. Everything below is already public or written to be public-safe.

## What exists (public facts)

- A design library of ~28 crocheted "bag dispenser" characters — dispensers shaped like a grocery-bag roll cover where the dispensing hole is the mouth/working-slot. All generic, trademark-clean, each concept file carrying: the joke, a sketch, materials, construction notes.
- Two real photos of crocheted pieces exist; more family photos will come over time. Concept-art renders (AI-generated product-style images) may also exist for some designs.
- The site's near-term shape, already decided in planning rounds: a single-file HTML **review room first** — the site's primary user (the maker) browses design cards and clicks ONE positive checkbox + optional short note per design (unchecked is not a veto); picks export via copy/JSON; zero network egress on the page. A public-facing site comes later, built from her picks; she gates the launch.
- A per-design "SEE" text block exists as the working idea: dense text descriptions of each design so text-only reviewers (including AI models) can evaluate designs without viewing images. Text-first.
- Hosting target: GitHub Pages (free, static); the known host path is a one-time Pages click on the repo settings, or simply sending the self-contained HTML file directly. No backend, no accounts, no analytics.

## Working question

**What is the best way for this website to be built, and the best way for the pictures to be posted?** Two sub-questions:

1. **Build path.** Given: review room now → public site later, static-only, free hosting, one non-technical primary user who clicks on her phone. Compare genuinely: single-file HTML kept simple vs a small static site generator vs hand-rolled multi-page static. What should stay invariant regardless of path? Where do people commonly over-build this kind of site?
2. **Picture pipeline.** From real family photos and concept renders to the site: formats/compression (phone photos, yarn texture), naming, alt text, and crucially **how concept renders and real finished pieces should be labeled so they are never confused** — the review user picks what to actually MAKE, so a concept image masquerading as a finished piece would corrupt her picks. Also: how the text-first SEE blocks and the pictures should relate. Privacy line: photos of crocheted objects only; no requirement that any person appear; the primary user gates all publication.

## Rules of engagement

- Not an audit; no verdicts about any person. UNDETERMINED and PASS are legitimate findings.
- The primary user's agency is the design constraint: her click must actually change what happens next, and unchecked must be free of penalty.
- Public-safe language only. Disagreement and shrugging are acceptable useful results.
